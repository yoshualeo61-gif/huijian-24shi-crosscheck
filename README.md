# 互見 huijian — 史料交叉比對

把散在二十四史各处的记载并排摆出，标出彼此对不上的地方。

**它不告诉你真相，它告诉你哪两条记载对不上。**

9. python huijian.py verify work/     （再跑一次，让基线生效）

## 核心设计：模型读，代码判

模型只做两件事：抽取（读文言，报人物和行为，附逐字原文）、人物归一。

其余全是普通 Python——矛盾检测、独载检测、纪年换算、事件对齐。

| | 错误形态 | 能否发现 |
|---|---|---|
| 模型抽错 | 引文对不上原文 | 能，程序自动拦截并计数 |
| 代码判错 | 规则定得不对 | 能，逻辑写在那儿，可以指着说这条错 |
| 模型直接下判断 | 流畅但错误的分析 | **不能** |

第三种是这个设计要避免的。不能被指着反驳的「洞见」没有研究价值。

## 它能做什么

下表的「实测」一栏全部来自郁洲案例在完整语料（2,412 卷）上跑一遍的结果，
不是设计意图。**一条也不要按意图读。**

| 能力 | 真语料实测 |
|---|---|
| 把同一人散在不同书、不同门类的记载聚合起来 | **可用。** 2.1 秒抓齐 24 人 57 条 |
| 每条附逐字原文、卷次、字符偏移，可回查 | **可用，这是最可靠的一环** |
| 同一事件的措辞差异（春秋笔法） | **抓到 1 条。**《梁书》「斩东昏」／《南史》「杀帝」。词表从这一条起头，远不完备 |
| 终局独载（记其人而不记其终） | **抓到 1 条**，即张稷案。但基线在南朝系各书上无法成立 |
| 记载冲突（互斥行为）、纪年歧异 | **真语料上从未触发过。** 既未证伪也未证实 |
| 单方独载（「仅见于某系」） | **已证伪。** 置换检验 p=1.000，不可作立场证据 |

**最要紧的一条实测结论：本案例 24 人里有 19 人只见于一部书。**
对这 19 人，交叉比对无从进行——工具现在会明说「孤证，帮不上忙，
只能告诉你去哪看」，不再把它包装成「仅见于某系」那种看似有内容的信号。
真能做比对的是 5 人：张稷、孙恩、刘裕、刘善明、马仙琕。
**这不是代码的毛病，是语料的覆盖。**

换句话说：**它是一把快而诚实的索引刀，不是立场偏向检测器。**
前者有实测支撑，后者没有。

## 它做不到什么

- 恢复没写下来的东西
- 回答「为什么」——动机类判断连专家之间一致性都只有 κ 0.27–0.32
- 只有一方记载时工作（立场轴塌陷）
- 给出可信度——报告里的「线索权重」只是排序，不是概率

## 语料

二十四史全文，来自 [hunterhug/china-history](https://github.com/hunterhug/china-history)。

**2,413 卷 / 2,205 万字**（已排除 621 个现代白话译文文件）。

已知缺口：《宋书》《南齐书》缺列传；《梁书》《陈书》《南史》《北史》只有部分卷；
时间止于《明史》。检索前先确认覆盖：

```bash
python3 -c "import pathlib;[print(d.name,len(list(d.iterdir()))) for d in sorted(pathlib.Path('corpus').iterdir())]"
```

**语料不随本仓库分发**，由 `fetch` 自行下载。原文属公有领域，
但现代点校本的句读与校勘可能有著作权，上游仓库未附授权声明，使用者自负。

**一处例外需说明：** `samples/` 下的两个 `.txt` 是郁洲案例的现成史料，
约 3.7 万字，摘自上述 [hunterhug/china-history](https://github.com/hunterhug/china-history)，
为的是让人不下载 250MB 语料也能看到输入长什么样。这批文本同样受上段的
不确定性约束——**它们不是本仓库的原创内容，本仓库也无权为其授权**。
要严格一些的话，删掉这两个文件不影响任何代码路径，
`samples/测试用_findings.json`（测试夹具）才是 `duizhao.py align` 需要的。

## 三条使用纪律

1. **每条结论都要回查原文。** 工具告诉你去哪看，不告诉你结论。
2. **别指望挖出新史料，指望读得快。** 优势是不知疲倦，不是更聪明。
3. **「为什么」类的判断不要信。** 谁、何时、何地可靠；动机不可靠。

## 当前状态 v0.2.6

v0.2.6 问的是一个很窄的问题：**把派生本当成独立证人，会多算多少？**
答案是：多算到让最响的那个信号整个站不住。

《南史》《北史》是李延寿唐修，删削南北朝各书而成。立场轴上每一个信号
都预设各书互为独立证人，而**派生本与其史源逐字雷同是常态**。两者一致
不构成互证（那只是抄录），两者不一致才有意义（那是改笔）。

实测这一处的代价：

| | 修改前 | 修改后 |
|---|---|---|
| 事件对照组数 | 22 | 19（10 独立 ＋ 9 源流） |
| 其中 `南朝系↔北朝系` | **0** | 0（语料所限，见下） |
| 「仅见于」旗标 | 24 | 4 |
| 新增「孤证」（权重 0） | — | 19 |
| 张稷案权重 | 8 | 5 |
| 回归断言 | 121 | 162 |

权重最高的那一组原本是《梁书》「以吴兴太守张稷**为**尚书左仆射」对
《南史》同句作「**爲**」——差别只有一个异体字，拿到权重 9。现在源流对
的锚定一致**一分不计**，只算其出入；全无出入的直接不报。

四处具体改动：

1. **`DERIVED_FROM` 源流关系表**，并据此算「独立史源数」。史源缺席时
   派生本自身仍算一个证人（《宋书》《南齐书》缺列传，《南史》往往是
   唯一所存），史源在场时它不添任何独立性。
2. **同月而干支日不同，又无共同行为 → 判为两件事。** 一个月里每个日
   干支最多出现一次。实测《梁书》「十二月丙申，以国子祭酒张稷为护军
   将军」曾与《南史》「十二月丙寅，…率兵入殿杀帝」配成一组。
3. **孤证不再报「仅见于」。** 只有一个独立史源时，「仅见于某系」是
   同义反覆，必然成立，不含任何立场信息——**这才是该旗标通不过置换
   检验的真正原因**。
4. **断代不重叠的书，其沉默不算无载。**《三国志》（184–280）不记
   张稷（卒 513）不是讳饰。

**一个诚实的负面结果：上面第 3、4 条都没能把那个旗标救回来。**
「仅见于」从 24 降到 4，置换检验仍是 p=1.000（n=4，虚无均值 4.83，
比实测还高）。改动的价值不在救活信号，而在**让工具报出自己的无能**，
而不是把 19 条「无从比对」包装成 24 条「发现」。

改动中我自己踩过一次坑，记在这里：源流对「没有已分类的出入就跳过」
曾把《梁书》「斩东昏」对《南史》「杀帝」**整组丢掉**——而那是本案例
最有价值的一条。词表叫不出名字，不等于此处无异。现在改为：两段引文
相似度 ≥0.88 才算纯抄录而丢弃，否则照报，并标为「出入未能归类」。
`tests/test_fixes.py` 的 15e 就是钉死这个回归的。

顺带把「斩东昏／杀帝」这一条标对了：它**不是**跨立场发现，是
《梁书》与其唐修派生本之间的发现。而这样反倒更锋利——因为《南史》
确实在抄《梁书》，把「东昏」（废帝贬谥）改成「帝」是看得见的编辑
动作，不是两个传统各说各话。报告现在称之为「改笔」。

## 之前：v0.2.5

**v0.2.5 是第一次在完整语料上跑过的版本。** 之前所有验证都用合成数据，
那是循环论证：自己写好抽得出来的文言，再确认抽得出来。

实测 2,412 卷 / 22,036,178 字。全库检索 2.1 秒，基线 6.7 秒。
文档里的两个数字独立对上了：PUA 字符 2,341 个分布在 740 卷（docs/07 的说法）,
阶段一 27 个 chunk（docs/07 的说法）。

**郁洲案例跑通了，头条发现站得住：** 《魏书》四处记张稷被徐玄明斩首
（延昌二年，513），而《梁书》本纪五度记其除授、直到天监十一年进号镇北将军,
此后再无音讯——`终局独载` 正确触发。同一事的措辞对立也抓到了：
张稷杀的那个人，《南史》作「率兵入殿**杀帝**」，《梁书》作「斩**东昏**」。

**同一次跑也否掉了本工具最常见的旗标。** 置换检验结果：

```
信號        實測   虛無均值      p
僅見於        24    24.00   1.000
終局獨載       1     0.96   0.964
```

打乱立场标签，信号一点不降——因为这批人多数只在一部书里出现，
「仅见于」量到的是**语料覆盖稀疏，不是立场差异**。这个旗标不能当立场证据用。
置换检验第一次跑就起了作用，这是它存在的理由。

真语料另外暴露了六个问题，全部已修并有回归测试
（详见 [06-已知局限](docs/06-已知局限.md)「四点五」一节）：

1. **现代白话混进语料，而逐字校验拦不住它**——译文确实逐字在 chunk 里。
   两种污染（附加译文段、整卷误标）各中 1 卷，已分别用结构界线和
   「的」密度堵住。
2. **阶段二的人名必须先筛**——「帝」在全语料出现 59,084 次，
   拿它当人名检索会灌出几千个无意义 chunk。
3. **基线在南朝系各书上无法成立**——《梁书》参照人数 0，《南史》2，
   因为本语料只有它们的本纪。报告如实写「无基线可比」，
   不拿 n=5 的比率充数。
4. **纪年歧异把反复除授当成一件事**——改为只对一生一次的行为判定。
5. **窗口截掉年号造成假歧异**——「二年二月」与「延昌二年二月」视为相容。
6. **事件层把相隔 38 年的两件事配成一组**——已知而相冲的纪年现在是否证。

另有两个**尚未修**的、需要改数据表才能解决的：孙恩的结局是「赴海自沈」，
而**自杀不在 18 个行为类型里**，他的终局无法编码；以及姓氏异文
（《魏书》作「刘晣」、《梁书》作「邓晣」，同官同事）不会被归一。

## 之前：v0.2.4

v0.2.4 加了标注环节（`biaozhu.py`）——**冲着「抽取精度未测」这一条**。

文档 05 早就写明了该怎么做（两轮、两人、算 κ），缺的不是方法而是脚手架：
就算你手标了 150 条，也没有东西把它们变成一个数字。现在有了。

工具做抽样与统计（分层抽样、Wilson 置信区间、Cohen's κ），
**判断仍然由人下**。三条轨道分开，因为它们的可标注性根本不同：

- **A 抽取精度**——「原文是否支持这条记载？」**可核验**，不是解释。
  成本最低，出头条数字。判断只看 evidence 那一句。
- **B 信号效度**——分两层：旗标是否正确描述记载（可核验）、
  讳饰是否最佳解释（解释性，**低 κ 是预期结果而非失败**）。
- **C 负对照**——被闸门拦下的条目。拦截率一直有报，
  **拦得对不对从来没量过**。误拦是召回的净损失。

```bash
python biaozhu.py sample work/ -n 30            # 第一轮：预试
python biaozhu.py score  work/ --second 乙.json  # 比 κ、改指南
python biaozhu.py sample work/ -n 150           # 第二轮：正式
python biaozhu.py score  work/                  # 精度 + 置信区间
```

n=150 且观测精度 0.9 时区间约 [0.84, 0.94]——够分辨「能用」和「不能用」，
而这是目前唯一需要分辨的事。流程见 [docs/05](docs/05-标注指南模板.md)。

## 之前：v0.2.3

v0.2.3 补的四层，都指着同一件事：**让权重从拍脑袋变成可以被指着反驳的数字。**

**独载基线（`huijian.py baseline`）。** 「某书记其人而不记其终」要成为讳饰的
证据，先得知道该书记同类人之死的正常比率。现在算得出来了：比率低于 30% 的书，
其沉默从 ⚠ 降为 ·，权重 5 → 2，基线数字写进报告理由。实测里它做的第一件事
就是**把本工具自己最响的信号调低**——这正是它该做的。基线本身的三处误差
写在文档 06，没有藏。

**月份与干支日锚定。** 《南齐书》与《南史》同记「二月丁卯」，此前一分未得；
现在同月 +2、同年同月又同干支 +3，样例的锚定权重从 11 升到 16。干支只在
月份之后近处采信（干支也用于纪年和人名），不换算成公元日。附带标出
日次歧异、闰月歧异；差一年又涉改元元年的「歧异」则降权，因为那很可能
只是改元月份的算法之异。

**置换检验（`huijian.py null`）。** 把立场标签在书之间打乱，重算各类信号，
给出 p 值。立场轴是全部跨立场信号的前提——打乱后信号不降，那些信号就不是
立场差异造成的。不需要金标准，不需要语料。注意有些信号按构造就与立场无关
（如终局互斥），p 接近 1 是对的，不是缺陷。

**知异索引（已知集合减法）。** 机制建好了，**索引是空的**：考异原书需自行
录入，代录即是编造。未载入索引时，报告顶部会写明「新颖性未知」并明确禁止
据此声称新发现。这不是解决，是把一个沉默的认知缺口变吵闹。

## 之前：v0.2.2

v0.2.2 补了两处——不是修 bug，是把两个已知缺口做掉：

**校验闸改成按地址重新切片。** 原先是子串测试 `ev in chunk`。一个 chunk
可能由同卷中数个不相邻的窗口拼成，横跨接缝的引文在 chunk 里看似连续，
在原书里却隔着几千字，子串测试会放它过关。现在 `scan()` 在卷的正规化全文上
检索并记下字符偏移，块内各段带绝对地址，接缝以 `……【中略】……` 标出，
`locate()` 要求引文完整落在单一段内。`verify --strict` 再回原卷切片逐字比对。
副产品是每条引文都有了 `(卷, 起点, 终点)` 的机器地址，回查不必再靠人眼找。

**人名归一进了 CLI，只提候选不自行合并。** 抽取规格要求 person 照原文写法、
不补姓氏，于是《宋书》的「善明」和《魏书》的「刘善明」各自成条：跨立场比对
落空，两边还都被误报「仅见于某系」。`verify` 现在会把候选写进
`aliases_suggested.json` 并在报告顶部警告，确认后存成 `aliases.json` 再跑一次
才生效，原写法保留在 `person_raw`。歧义（一个短名对上多个长名）不给建议值。
字、号、小名覆盖不到，见文档 06。

## 之前：v0.2.1

**一把能用的刀，不是一篇能发的论文。**

v0.2.1 修了三处会悄悄给出错误结果的缺陷（`python tests/test_fixes.py` 可复现）：

1. **检索去重会跨书丢段。** 去重 key 原是全局的 `ctx[:45]`。《南史》删削
   《宋书》而成，成段雷同者只留下排序在前的一本——被丢掉的往往正是原始史源，
   交叉比对因此少掉一方，还会误报「单方独载」。现在 key 带上书名，
   书内摺叠照旧，书间并置不受影响。
2. **同名年号悄悄换算成另一朝。** `泰始二年` 在《晋书》是 266、在《宋书》是 466，
   旧版一律给 466；`建武二年` 在《后汉书》是 26，旧版给 495。错误的年份还会在
   `pair_score()` 里加 3 分，凭空造出「同年」锚定。现在按来源书的记事起讫消歧，
   定不下来就返回 `None`——与 `to_year()` 文档里那句「不猜」一致。
3. **《南史》《北史》被当成南北朝当代的独立证人。** 二者是唐修派生本，
   计入南／北朝系会虚增立场轴的独立性。改归「唐修」，与介绍幻灯片和
   `samples/` 夹具的标注一致（此前代码与自带样例互相矛盾）。

另外：输出重定向到文件时不再因本地代码页而崩（Windows 上
`search 郁洲 > out.txt` 原会抛 `UnicodeEncodeError`）；`verify` 不再要求
语料存在（它只读 `work/*.json`）。

所有判定参数（阈值、立场词表、互斥集）**未经标注验证**。
`PAIRS` 里的 `("除授","罢黜")` 是**故意留的错误规则**，会误报——
一个人先任后免是正常序列。留着是为了让你第一次跑就明白规则需要校准。
正式使用前删掉它。

抽取精度**仍未测**——但现在测得动了：`biaozhu.py` 把抽样和统计都做好了，
缺的只是坐下来标 150 条。标完才有数字，没标之前「能用」靠的是设计而非证据。

要从「能用」到「可发表」，还缺两人独立标注的一致性数据，以及知异索引
（没有它就无从声称任何「新发现」）——见文档 05 和 06。
