# 06 · 已知局限

决定要不要用之前，先读这个。

## 一、根本性的

**它不能恢复没写下来的东西。** 任何方法都不能。

如果某件事三种史书都没记，它不在语料里，模型变不出来。
这个工具挖的是**散在各处、没人拼过的东西**——那个量其实很大，但边界是明确的。

**「为什么」类的问题不在能力范围内。** 谁、何时、何地是文本表面的事实；
动机需要重建意图，连合格专家之间的一致性都只有 κ 0.27–0.32。
机器不可能比金标准本身更可靠。

**「谁是叛徒」不是事实问题。** 同一行为，在两个框架下有两套描述，
读再多史料也不能消解，因为分歧不在于发生了什么。
可答的版本是「谁降了？各书如何记述？」

## 二、参数与验证

**所有判定参数都未经验证。**

| 参数 | 位置 | 状态 |
|---|---|---|
| 锚定阈值 4 | `duizhao.align()` | 拍的 |
| 锚定权重 3/2/3/1 | `pair_score()` | 拍的 |
| 终局互斥集 | `huijian.TERMINAL` | 拍的 |
| 成对互斥 | `huijian.PAIRS` | 拍的，且已知含一条错误规则 |
| 立场词表 | `duizhao.STANCE_LEX` | 拍的，误报率未知 |
| 去重 key 长度 45 | `huijian.scan()` | 拍的（去重范围已限定在同一部书内，见下）|
| 归一规则：后缀差 1–3 字 | `huijian.alias_candidates()` | 拍的；只提候选，需人确认 |
| 书名跨度断限 | `duizhao.BOOK_SPAN` | 宽松取的，只为排除百年量级误判 |
| 终局词表 | `huijian.TERMINAL_LEX` | 拍的；只收歧义小的词，宁漏不滥 |
| 基线窗口 120 字 | `huijian.terminal_rate()` | 拍的 |
| 基线阈值 0.3 / 0.7 | `huijian.analyse()` | 拍的，决定沉默要不要降权 |
| 同月 +2 / 同干支 +3 | `duizhao.pair_score()` | 拍的 |
| 日次、闰月歧异 +3 | `duizhao.diverge()` | 拍的 |
| 分段 1400 字 | `huijian.chunks()` | 拍的 |

**抽取精度未测。** 没有金标准，没有 precision/recall，没有和基线比过。
报告里那个「线索权重」只是排序参考，**不是置信度**，不要当成可信度引用。

**「已知集合」有了机制，但索引是空的。** 系统仍分不清哪条是新发现、
哪条是钱大昕两百年前就写过的。现在的改动只是**让这件事变得吵闹**：
未载入知异索引时，`verify` 会在报告顶部写明「新颖性未知」并明确禁止据此
声称新发现。

索引格式见 `data/zhiyi.example.json`，放在 `work/zhiyi.json` 或 `data/zhiyi.json`
即被读取，命中的人物在报告里以 ◆ 标出。

**仓库不附任何真实条目。** 考异原书（钱大昕《廿二史考异》、王鸣盛
《十七史商榷》等）需自行取得并录入——代录即是编造，与本工具的设计相悖。
索引没建起来之前，**仍然不要声称任何「新发现」**。

另外：索引无命中有两种解释——确属前人未及，或索引覆盖不足。
两者无法由此分辨，报告会照实说。

## 三、语料

**宋书、南齐书缺列传。** 上游仓库只有本纪和志。
传记材料是人物细节的主要来源，缺了这部分，人物层结果不完整。

**南史、北史、梁书、陈书等只有部分卷。** 检索前先确认覆盖：

    python3 -c "import pathlib; [print(d.name, len(list(d.iterdir()))) for d in sorted(pathlib.Path('corpus').iterdir())]"

**时间边界止于明史。** 明清之际及以后的题目，语料里没有。

**繁简混杂。** 同一部书内部可能两种字形并存，检索必须做变体扩展。

**上游仓库文本未经校勘。** 与中华书局点校本的异同未核对。

## 四、实现层

**拼接已拦住，但校验仍以 chunk 为界。** 校验不再是子串测试。
`scan()` 在卷的正规化全文上检索，记下每个窗口的字符偏移；`_mkchunks()`
把同卷窗口并段后装块，块内各段的绝对偏移都记在 `chunks.json` 里，
不相邻的段之间插 `……【中略】……`。`locate()` 要求引文**完整落在单一段内**,
横跨接缝即判拼接。`verify --strict` 再按地址回原卷重新切片逐字比对。

残余缺口：`locate()` 取段内第一次出现的位置。若同一引文在该段内出现多次，
地址指向的是第一处，不一定是模型所据的那一处——对回查无妨，
对"精确到第几次出现"的用途不够。

**CLI 的人物归一只提候选，不自行合并。** `verify` 跑完会把候选写进
`work/aliases_suggested.json` 并在报告顶部警告；确认后存成 `work/aliases.json`
（`{"善明": "刘善明"}`）再跑一次才生效，原写法保留在 `person_raw`。

规则是确定性的：短名为长名的真后缀，且长名多出 1–3 字（姓氏的长度）。
一个短名对上多个长名时标 `ambiguous` 并且**不给建议值**。

**它覆盖不到字、号、小名、追赠官称。**「卧龙」对不上「诸葛亮」，
这类要靠外部人名权威表，没建。所以归一后仍可能有同一人被算成两个。
**不归一的后果是实测过的**：「善明」（《宋书》）与「刘善明」（《魏书》）
不合并时各自成条，跨立场比对落空，而且两边都被误报「仅见于某系」——
见 `tests/test_fixes.py` 第 7 项。

**纪年仍不处理月份边界，但差一年的歧异会被降权。** 若某年年中改元，
那年前几个月属旧年号，换算会错一年。现在 `diverge()` 遇到「差恰好一年
且一方为改元元年」时把权重从 5 降到 2 并说明理由——**它不解决换算，
只是不再把很可能的假歧异报成强信号**。

真正要解决，需要逐年号的改元月份表，没建。

**同名年号靠书名跨度消歧，不够精细。** 历代重用的年号（泰始、建武、太和、
正始……）字面完全相同，`to_year()` 用 `BOOK_SPAN` 按来源书的记事起讫挑唯一解。
书名缺失或仍不唯一时返回 `None`（不猜）。代价是：一部书追述前朝年号时
（如《晋书》提曹魏太和）可能落在本书跨度之外而换算失败。
`BOOK_SPAN` 的断限是宽松取的，只求排除百年量级的误判。

**事件对齐是 O(n²)。** 目前 n 是单次检索的抽取条数（几十到几百），没问题。
要放大到语料级必须先做粗筛。

**《南史》《北史》不计入南北朝系。** 二者是李延寿唐修，删削《宋书》《南齐书》
《魏书》等而成，不是南北朝当代的独立证人。立场表把它们归入「唐修」。
后果是**南朝系的覆盖进一步变薄**——《宋书》《南齐书》本就缺列传（见上），
再排除《南史》，南朝系可用材料不多。这是诚实的代价：宁可承认一方材料不足，
也不要把派生本算成独立的第二个证人。

**独载检测的基线已建，但只是可审的近似。** 「没记载」既可能是讳饰，
也可能是该书体例本就不记这类事，也可能是散佚。`huijian.py baseline` 现在算
**终局著录率**：对每个（人名, 书）组合，该书若提及此人，其名附近是否出现终局
用语。比率低于 30% 的书，其沉默在报告里从 ⚠ 降为 ·，权重 5 → 2，
并把基线数字写进理由。

**这个基线本身有误差，三处：**

1. **词表是拍的。** `TERMINAL_LEX` 只收歧义小的词，所以漏（真记了死而用词不在表内）
   多于滥。漏会压低比率，而比率一低，沉默就显得正常——**方向上偏保守，会遮真信号**。
2. **归属靠「中间不得夹着别人」。** 本纪一段之内常列数人数死，不加这条，
   邻人的死会算到自己头上。实测中正是这个条件漏掉时把比率从 50% 刷到 100%
   （见 `tests/test_fixes.py` 11b）。但它仍只是启发式：同一人多种称法、
   或两人之间无名可隔时照样会误判。
3. **对照群体是你这次检索到的人，不是随机样本。** n 小的时候比率不稳，
   报告里的 `n=` 就是让你看这个。n 只有个位数时不要当比率用。

**它仍然不是结论，只是把「线索」从拍脑袋改成了可以指着反驳的数字。**
「是否提及」的著录率（独载检测的另一半）还没算。

**没有重试逻辑。** API 失败就跳过那一段并打印。这是有意的，避免静默掩盖问题。

## 五、这个工具的定位

**它是一把能用的刀，不是一篇能发的论文。**

作为读书辅助工具：现在就能用，能压缩大量机械劳动，
产出的每一条都能回查原文。

作为研究方法：还差三样——任务定义、标注框架、一致性数据。
差距大约一年，主要成本不是写代码，是找到两个愿意标几千条的人。

## 六、相关工作

这个方向已经有人做，不是空白：

- Sturgeon 2018，早期汉籍文本重用，Chinese Text Project
- Vierthaler & Gelein，基于 BLAST 的对齐器
- Nehrdich，汉文佛典平行段落
- Deng, Yang & Wang 2022，《史记》《汉书》互文对比
- Wang, Si & Wang 2026，*Beyond Similarity*，span 落地 + 专家裁定基准
- Assael et al., Nature 2025，拉丁碑铭的生成式语境化

**Beyond Similarity 那篇和本工具的设计高度重合**（逐字校验、显式弃权、
判断不交给模型），而且做了本工具没做的专家裁定基准。要往学术方向走，先读那篇。

尚未被占的方向：跨汉字圈（韩国汉文、日本汉文、越南汉文）、
矛盾关系（而非引用关系）、讳饰检测的形式化。
