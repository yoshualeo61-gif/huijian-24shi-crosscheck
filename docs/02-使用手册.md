# 02 · 使用手册

## huijian.py — 人物层

### `fetch`

```bash
python huijian.py fetch
```

下载并转换语料。无参数。可重复运行，已 clone 则跳过下载，但会重新转换文本。

想换语料源，改 `huijian.py` 顶部的 `REPO` 常量，并检查 `html_to_text()` 的外壳剥离规则是否还适用。

### `search`

```bash
python huijian.py search TERM [--also 别名...] [--window N]
```

纯本地检索，**不调 API，不花钱**。

| 参数 | 默认 | 说明 |
|---|---|---|
| `TERM` | 必填 | 主检索词 |
| `--also` | 无 | 额外别名，空格分隔。可给任意多个 |
| `--window` | 200 | 命中点前后各取多少字作为上下文 |

输出按立场分组，去重（同一段被多个检索词命中只算一次）。

**`--also` 该给什么**：同一地点的历史异名、行政沿革名、俗称。以郁洲为例：

```bash
python huijian.py search 郁洲 --also 郁州 鬱州 田横岛 环州 东海县 青冀二州
```

繁简变体由 opencc 自动处理，不用手工加。

### `dossier`

```bash
python huijian.py dossier TERM [--also ...] [--window N] -o 目录
```

同 `search`，但把结果按立场写成若干 txt 文件，便于贴进标注界面。

```
out/郁洲_南朝系.txt   9 段  3,557 字
out/郁洲_北朝系.txt  18 段  7,193 字
out/郁洲_唐修.txt     6 段  2,402 字
```

### `run`

```bash
python huijian.py run TERM [--also ...] [--window N] -o 目录
                          [--limit N] [--dry-run] [--debug]
```

全流程：检索 → 抽取 → 校验 → 归一 → 分析 → 报告。**这一步调 API。**

| 参数 | 用途 |
|---|---|
| `--dry-run` | 只列出将发出的请求，不调 API。**每次正式跑之前都该先跑这个** |
| `--limit N` | 最多调用 N 次就停。控成本，也便于小样本调试 |
| `--debug` | 逐条打印模型返回条数和每一条被拦截的伪引 |

产出：

- `TERM_report.txt` — 人读的报告
- `TERM_findings.json` — 结构化结果

### `baseline`

```bash
python huijian.py baseline work/
```

算**终局著录率**：对每个（人名, 书）组合，该书若提及此人，其名附近是否出现
终局用语（卒、薨、见杀、伏诛……）。比率 = 有终局者 / 提及者。

这是独载检测缺的基线。「某书记其人而不记其终」要成为讳饰的证据，
先得知道该书记同类人之死的正常比率。写入 `work/baseline.json`，
下次 `verify` 自动读取：比率低于 30% 的书，其沉默权重从 5 降到 2，
并把基线数字写进报告理由里。

归属规则：名字与终局用语之间若夹着另一个对照名，不算本人的
（本纪一段之内常列数人数死）。规则在 `_attributable()`，可审可改。

**需要语料在位。**

参照群体默认取各书列传开篇定式「某字某，某地人也」的传主姓名
（`--cohort reference`，每书上限 `--limit 400`），而不是本次检索结果——
后者每部书只有个位数的 n，比率站不住。`--cohort findings` 可切回去，
但会警告。

`n` 低于 `BASELINE_MIN_N`（20）的书，其比率**不参与调权重**，
报告里照实写「无基线可比」。实测《梁书》《南史》的参照人数分别是
0 和 2——本语料只有它们的本纪，所以基线对南朝系各书无法成立。

### `null`

```bash
python huijian.py null work/ --iters 2000
```

**置换检验。** 把立场标签在书之间打乱（保留书内结构），重算各类信号，
给出实测值、虚无均值、虚无 95 分位和 p 值。

立场轴是全部跨立场信号的前提。打乱标签后信号量不降，那些信号就不是
立场差异造成的，权重也就没有意义。不需要金标准，不需要语料。

注意：有些信号**按构造就与立场无关**（如「终局互斥」只看同一人的行为集），
它们的 p 值本来就该接近 1，不是缺陷。要看的是「仅见于」「终局独载」
这类声称依赖立场的信号。

## duizhao.py — 事件层

### `eras`

```bash
python duizhao.py eras 延昌二年 天监十二年 崇祯七年
```

纪年换算。输出：

```
延昌二年             → 513 年（延昌2）
天监十二年            → 513 年（天监12）
崇祯七年             → 未收，不猜
```

**未收年号返回「不猜」，不外推。** 要加年号，编辑 `duizhao.py` 里的 `ERAS` 表，格式 `("年号", 元年公元, "立场")`。

注意表是按年号字符串长度倒序排的，所以「中大通」不会被「大通」吃掉。加新年号后不用手动排序，代码里有 `ERAS.sort()`。

### `align`

事件层对齐。锚定现在包含**月份与干支日**：同年同月又同干支，
两条几乎不可能不是同一天。干支只在月份之后近处采信——干支也用于纪年
和人名，离开「某月」的上下文就不可靠。干支日不换算成公元日
（那需要连续历表），只作字面比对。



```bash
python duizhao.py align findings.json [-t 阈值] [-o 输出文件]
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `-t` | 4 | 锚定分数阈值，低于此值不配对 |
| `-o` | 无 | 同时写入文件 |

锚定打分规则（见 `pair_score()`）：

| 条件 | 分 |
|---|---|
| 同人物 | +3 |
| 同地点 | +2 |
| 同年（换算后） | +3 |
| 相邻年 | +1 |
| 行为重叠 | +1 |

**只配跨立场的对。** 同一立场内部的两条记载不会被配对——因为独载和曲笔只在跨立场时才有意义。

阈值怎么调：

- 结果太少 → 降到 3，甚至 2
- 噪声太多 → 升到 5 或 6
- **这个数没有标注依据，必须自己校准**

## biaozhu.py — 标注层

### `sample`

```bash
python biaozhu.py sample work/ -n 150 --flags 40 --rejects 30
```

从 `work/findings.json` 和 `work/dropped.json` 分层抽样，产出：

- `work/annot_sample.json` —— 在这个文件里把 `verdict` 的 `null` 填掉
- `work/annot_sample.txt` —— 给人读的本子，含每轨的判断指南

分层是必要的：纯随机抽 150 条，只出现三次的旗标很可能一条都抽不到，
那一类就永远没有数字。A 轨按（立场, 是否含终局行为）分层，
B 轨按旗标类别，C 轨按拦截理由。`--seed` 可复现。

### `score`

```bash
python biaozhu.py score work/
python biaozhu.py score work/ --second 乙的标注.json
```

算 A 轨各字段精度（Wilson 95% 区间）、B 轨 reading 正确率与
interpretation 分布、C 轨误拦率。给了 `--second` 就算 Cohen's κ。

**拼错的判断值会报错而不是略过**——标注文件是手写的，
默默跳过会让分母无声缩水，精度看起来反而更好。

## 常用工作流

### A. 探索一个新题目

```bash
# 1. 先看有没有材料
python huijian.py search 皮岛 --also 椵岛 东江镇

# 2. 材料够就估成本
python huijian.py run 皮岛 --also 椵岛 --dry-run

# 3. 小跑
python huijian.py run 皮岛 --also 椵岛 -o out/ --limit 15

# 4. 看结果决定要不要全跑
```

### B. 准备标注数据

```bash
python huijian.py dossier 郁洲 --also 郁州 -o annot/
# 把 annot/ 里的文件贴进 ui/shiyuan_reader.jsx，逐条标记，导出 JSON
```

### C. 加自己的语料

把纯文本放进 `corpus/书名/卷名.txt`，然后在 `huijian.py` 的 `STANCE` 字典里给这部书加立场标签：

```python
STANCE = {
    ...
    "永历实录": "南明系",
    "爝火录": "南明系",
}
```

**立场标签决定独载怎么算。** 标错了，整个独载检测就没意义。

立场不必是「南朝/北朝」，任何有对立关系的轴都行：官修/私撰、本传/墓志、宋/金、明/清。

## 修改判定规则

### 行为类型表

`huijian.py` 里的 `ACTS`。改了要同步改 prompt——prompt 里的 `{acts}` 是从这个表填的，所以只改表就够。

```python
ACTS = ["除授", "罢黜", "赴任", "征战", ...]
```

**别加太多。** 类型越多，模型分类越不稳。目前 18 个已经偏多。

### 互斥规则

```python
TERMINAL = {"死于战", "病卒", "被杀", "归降", "被俘"}   # 任两者并存＝硬矛盾
PAIRS = [("战胜", "战败"), ("除授", "罢黜")]
```

`TERMINAL` 是「终局互斥集」——一个人不可能既战死又归降。集合内任意两个并存就报硬矛盾。

`PAIRS` 是成对互斥，适合那些不属于终局但仍不能同真的。

**注意 `("除授", "罢黜")` 这一对其实有问题**：一个人先被任命后被罢免是完全正常的，不是矛盾。这条留在里面是故意的，让你第一次跑就能看到一条明显的误报，从而理解「规则需要校准」这件事。真用的时候应该删掉。

### 立场词表

`duizhao.py` 里的 `STANCE_LEX` 和 `OPPOSED`。

```python
STANCE_LEX = {
    "歸附": ["内附", "归诚", "来降", ...],
    "叛離": ["叛", "反", "谋反", ...],
    ...
}
OPPOSED = [("歸附", "叛離"), ("敵來", "我往")]
```

加词时注意**假阳性**：「反」字在文言里极常见（「反之」「反覆」），会大量误触发。目前这个表覆盖率和误判率都没测过。
