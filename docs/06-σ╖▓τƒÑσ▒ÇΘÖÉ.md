# 06 · 已知局限

决定要不要用之前，先读这个。

## 一、根本性的

**它不能恢复没写下来的东西。** 任何方法都不能。

如果某件事三种史书都没记，它不在语料里，模型变不出来。
这个工具挖的是**散在各处、没人拼过的东西**——那个量其实很大，但边界是明确的。

**「为什么」类的问题不在能力范围内。** 谁、何时、何地是文本表面的事实；
动机需要重建意图，连合格专家之间的一致性都只有 κ 0.27–0.32。
机器不可能比金标准本身更可靠。

**「谁是叛徒」不是事实问题。** 同一行为，在两个框架下有两套描述，
读再多史料也不能消解，因为分歧不在于发生了什么。
可答的版本是「谁降了？各书如何记述？」

## 二、参数与验证

**所有判定参数都未经验证。**

| 参数 | 位置 | 状态 |
|---|---|---|
| 锚定阈值 4 | `duizhao.align()` | 拍的 |
| 锚定权重 3/2/3/1 | `pair_score()` | 拍的 |
| 终局互斥集 | `huijian.TERMINAL` | 拍的 |
| 成对互斥 | `huijian.PAIRS` | 拍的，且已知含一条错误规则 |
| 立场词表 | `duizhao.STANCE_LEX` | 拍的，误报率未知 |
| 去重 key 长度 45 | `huijian.scan()` | 拍的（去重范围已限定在同卷内，见下）|
| 分段 1400 字 | `huijian.chunks()` | 拍的 |

**抽取精度未测。** 没有金标准，没有 precision/recall，没有和基线比过。
报告里那个「线索权重」只是排序参考，**不是置信度**，不要当成可信度引用。

**没有「已知集合」。** 系统分不清哪条是新发现、哪条是钱大昕两百年前就写过的。
建这个减法掩码之前，不要声称任何「新发现」。

## 三、语料

**宋书、南齐书缺列传。** 上游仓库只有本纪和志。
传记材料是人物细节的主要来源，缺了这部分，人物层结果不完整。

**南史、北史、梁书、陈书等只有部分卷。** 检索前先确认覆盖：

    python3 -c "import pathlib; [print(d.name, len(list(d.iterdir()))) for d in sorted(pathlib.Path('corpus').iterdir())]"

**时间边界止于明史。** 明清之际及以后的题目，语料里没有。

**繁简混杂。** 同一部书内部可能两种字形并存，检索必须做变体扩展。

**上游仓库文本未经校勘。** 与中华书局点校本的异同未核对。

## 四、实现层

**子串匹配不防拼接。** 逐字校验用的是 `ev in ck`，
能拦住改写和虚构，但如果模型拼接原文中不相邻的两段且结果恰好连续，理论上拦不住。
更严格的做法是记录字符偏移再重新切片。

**CLI 没有人物归一。** 只有 React 界面有。CLI 里「善明」和「刘善明」算两个人。

**纪年不处理月份边界。** 若某年年中改元，那年前几个月属旧年号，会算错一年。

**同名年号靠书名跨度消歧，不够精细。** 历代重用的年号（泰始、建武、太和、
正始……）字面完全相同，`to_year()` 用 `BOOK_SPAN` 按来源书的记事起讫挑唯一解。
书名缺失或仍不唯一时返回 `None`（不猜）。代价是：一部书追述前朝年号时
（如《晋书》提曹魏太和）可能落在本书跨度之外而换算失败。
`BOOK_SPAN` 的断限是宽松取的，只求排除百年量级的误判。

**事件对齐是 O(n²)。** 目前 n 是单次检索的抽取条数（几十到几百），没问题。
要放大到语料级必须先做粗筛。

**《南史》《北史》不计入南北朝系。** 二者是李延寿唐修，删削《宋书》《南齐书》
《魏书》等而成，不是南北朝当代的独立证人。立场表把它们归入「唐修」。
后果是**南朝系的覆盖进一步变薄**——《宋书》《南齐书》本就缺列传（见上），
再排除《南史》，南朝系可用材料不多。这是诚实的代价：宁可承认一方材料不足，
也不要把派生本算成独立的第二个证人。

**独载检测缺基线分布。** 「没记载」既可能是讳饰，也可能是该书体例本就不记这类事，
也可能是散佚。要区分，需要知道「同类人物在该类书中的正常著录率」——这个没建。
所以独载标记只是**线索**，不是**结论**。

**没有重试逻辑。** API 失败就跳过那一段并打印。这是有意的，避免静默掩盖问题。

## 五、这个工具的定位

**它是一把能用的刀，不是一篇能发的论文。**

作为读书辅助工具：现在就能用，能压缩大量机械劳动，
产出的每一条都能回查原文。

作为研究方法：还差三样——任务定义、标注框架、一致性数据。
差距大约一年，主要成本不是写代码，是找到两个愿意标几千条的人。

## 六、相关工作

这个方向已经有人做，不是空白：

- Sturgeon 2018，早期汉籍文本重用，Chinese Text Project
- Vierthaler & Gelein，基于 BLAST 的对齐器
- Nehrdich，汉文佛典平行段落
- Deng, Yang & Wang 2022，《史记》《汉书》互文对比
- Wang, Si & Wang 2026，*Beyond Similarity*，span 落地 + 专家裁定基准
- Assael et al., Nature 2025，拉丁碑铭的生成式语境化

**Beyond Similarity 那篇和本工具的设计高度重合**（逐字校验、显式弃权、
判断不交给模型），而且做了本工具没做的专家裁定基准。要往学术方向走，先读那篇。

尚未被占的方向：跨汉字圈（韩国汉文、日本汉文、越南汉文）、
矛盾关系（而非引用关系）、讳饰检测的形式化。
