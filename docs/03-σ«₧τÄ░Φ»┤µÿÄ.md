# 03 · 实现说明

写给要改代码的人。

## 核心原则

**模型读，代码判。**

模型只有两个职责：抽取（读一段文言，报出人物和行为，附逐字原文）、归一（判断「善明」和「刘善明」是不是同一人）。

其余全部是普通 Python：矛盾检测、独载检测、纪年换算、事件对齐、排序。

为什么这样切：

| | 错误形态 | 能否发现 |
|---|---|---|
| 模型抽错 | 引文对不上原文 | 能，程序自动拦截 |
| 代码判错 | 规则定得不对 | 能，逻辑写在那儿，可以指着说这条错了 |
| 模型直接下判断 | 流畅但错误的分析 | **不能**，它没引用任何具体的假话 |

第三种是这个设计要避免的。一个「洞见」如果不能被指着反驳，它就没有研究价值。

## 数据流

```
HTML 语料
   │ html_to_text()      剥网页外壳，排除译文
   ▼
corpus/书名/卷名.txt
   │ variants()          opencc 繁简扩展 + 用户别名
   │ scan()              全库扫描，取上下文，去重
   ▼
hits: [(书, 卷, 立场, 命中词, 上下文)]
   │ chunks()            按句切分，默认 1400 字
   │ call_api()          ← 唯一的模型调用点
   │ 逐字校验             ev in ck ? 保留 : 丢弃并计数
   ▼
rows: [{person, title, place, time, acts, evidence, book, juan, stance}]
   │ analyse()           纯代码
   ▼
findings.json
   │ duizhao.align()     纯代码
   ▼
事件对照
```

## huijian.py 关键函数

### `html_to_text(p)`

剥 HTML 标签，unescape，按行过滤网页外壳（「首页」「目录」「下一节」等）。

**这个函数和语料源强耦合。** 换了语料源，`junk` 元组里的关键词要重写。

### `variants(term, extra)`

opencc 双向转换加用户别名，返回去重排序的列表。

注意 opencc 的 `s2t` 有过度转换问题：`郁` → `鬱` 在郁洲这个场景恰好是对的（两种写法都有文献依据），但一般情况下 `郁郁葱葱` 的 `郁` 不该变成 `鬱`。

这里选择**宁滥勿缺**——多检索几个变体，代价只是多几段无关命中，由后续人工筛掉。检索阶段应该偏向召回。

### `scan(terms, window)`

全库扫描。去重用的 key 是上下文前 45 字符——同一段被多个检索词命中，或者语料里有重复文件（`南史/卷一-原文.txt` 和 `南史/-卷一-原文.txt`），只保留一条。

**这个去重是启发式的**，45 这个数没有依据。太短会误合并，太长会漏合并。

### `chunks(text, n)`

按 `[。！？；\n]` 的 lookbehind 切分，累加到 n 字为止。保证不切断句子。

n 默认 1400。太大模型会漏抽，太小会切断人物的上下文。

### `call_api(prompt, key)`

用 `urllib` 直接发请求，不依赖 SDK。返回解析后的 JSON 数组。

解析策略：剥掉 markdown 代码块标记，取第一个 `[` 到最后一个 `]`。模型偶尔会加前言，这样能兜住。

**没有重试逻辑。** 失败就跳过这一段并打印错误。这是有意的——静默重试会掩盖系统性问题。

### 逐字校验

```python
if len(ev) >= 4 and ev in ck:
    ...保留
else:
    dropped += 1
```

**这是整个系统防杜撰的唯一硬保证。**

`len(ev) >= 4` 是为了排除模型返回过短片段（「曰」「之」这种在任何文本里都能匹配上）。

`ev in ck` 是朴素子串匹配。更严格的做法是记录字符偏移再重新切片比对——那篇 Beyond Similarity 论文就是这么做的，能防住「模型拼接了原文中不相邻的两段」这种情况。当前实现防不住。

### `analyse(rows, all_stances)`

纯代码推断层。按人名聚合后逐条应用规则：

1. **终局互斥** — `TERMINAL` 集合内任两者并存，权重 5
2. **成对互斥** — `PAIRS` 里的对，权重 4
3. **纪年歧异** — 同一人同一行为绑了不同 time 字符串，权重 4
4. **终局独载** — 多立场都记其人，但某个终局行为只有一方记，权重 5
5. **人物独载** — 此人只见于部分立场，权重 3
6. **多处互见无冲突** — 兜底，权重 1

第 4 条比第 5 条强：两方都记这个人，说明不是材料散佚，那么单方记其死就更可能是选择性沉默。

**这条规则是跑真实数据时才发现该加的**，不是预先设计的。原本张稷只拿到权重 1，因为他在南北两系都有记载（独载不触发），而「除授」和「被杀」不互斥（硬矛盾不触发）。加了终局独载后跳到 5。

## duizhao.py 关键函数

### `to_year(text)`

从「延昌二年」这样的字符串抽出公元年。

流程：遍历 `ERAS`（已按年号长度倒序），正则匹配 `年号 + 中文数字 + 年`，用 `cn_num()` 转数字，返回 `元年公元 + n - 1`。

**未收年号返回 None**，不做任何外推。

已知缺陷：不处理改元当年的月份边界。如果某年五月改元，那年前五个月属于旧年号，这里会算错一年。

### `pair_score(a, b)`

三重锚定打分。事件层没有姓名这种硬锚点，所以靠人物、地点、纪年、行为四个维度叠加。

权重 3/2/3/1 是拍的。

### `lex_tags(text)` 与 `diverge()`

立场词表匹配加分歧分类。

`diverge()` 输出四类：纪年歧异、立场用语对立、蔑称、行为不重叠。

### `align(rows, threshold, cross_stance_only)`

两两组合（`itertools.combinations`），过阈值的留下。

**复杂度是 O(n²)。** 目前 n 是单次检索命中的抽取条数（几十到几百），没问题。如果要放大到语料级，这里必须先做粗筛。

## 要扩展的话

按价值排序：

1. **span 偏移**而非子串匹配（防拼接式伪引）
2. **CLI 接入人物归一**（目前只有 React 版有，CLI 里「善明」和「刘善明」算两个人）
3. **纪年的月份边界**处理
4. **独载检测的基线分布**——需要知道「同类人物在该类书中的正常著录率」，才能区分讳饰与体例
5. **事件层的实体对齐**——目前靠字符串相等，应该用归一后的 id
