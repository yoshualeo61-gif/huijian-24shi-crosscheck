# 03 · 实现说明

写给要改代码的人。

## 核心原则

**模型读，代码判。**

模型只有两个职责：抽取（读一段文言，报出人物和行为，附逐字原文）、归一（判断「善明」和「刘善明」是不是同一人）。

其余全部是普通 Python：矛盾检测、独载检测、纪年换算、事件对齐、排序。

为什么这样切：

| | 错误形态 | 能否发现 |
|---|---|---|
| 模型抽错 | 引文对不上原文 | 能，程序自动拦截 |
| 代码判错 | 规则定得不对 | 能，逻辑写在那儿，可以指着说这条错了 |
| 模型直接下判断 | 流畅但错误的分析 | **不能**，它没引用任何具体的假话 |

第三种是这个设计要避免的。一个「洞见」如果不能被指着反驳，它就没有研究价值。

## 数据流

```
HTML 语料
   │ html_to_text()      剥网页外壳，排除译文
   ▼
corpus/书名/卷名.txt
   │ variants()          opencc 繁简扩展 + 用户别名
   │ scan()              全库扫描，取上下文，去重
   ▼
hits: [(书, 卷, 立场, 命中词, 上下文)]
   │ chunks()            按句切分，默认 1400 字
   │ call_api()          ← 唯一的模型调用点
   │ 逐字校验             ev in ck ? 保留 : 丢弃并计数
   ▼
rows: [{person, title, place, time, acts, evidence, book, juan, stance}]
   │ analyse()           纯代码
   ▼
findings.json
   │ duizhao.align()     纯代码
   ▼
事件对照
```

## huijian.py 关键函数

### `html_to_text(p)`

剥 HTML 标签，unescape，按行过滤网页外壳（「首页」「目录」「下一节」等）。

**这个函数和语料源强耦合。** 换了语料源，`junk` 元组里的关键词要重写。

### `variants(term, extra)`

opencc 双向转换加用户别名，返回去重排序的列表。

注意 opencc 的 `s2t` 有过度转换问题：`郁` → `鬱` 在郁洲这个场景恰好是对的（两种写法都有文献依据），但一般情况下 `郁郁葱葱` 的 `郁` 不该变成 `鬱`。

这里选择**宁滥勿缺**——多检索几个变体，代价只是多几段无关命中，由后续人工筛掉。检索阶段应该偏向召回。

### `scan(terms, window)`

全库扫描。去重用的 key 是 `(书名, 上下文前 45 字符)`——同一段被多个检索词命中，或者语料里有重复文件（`南史/卷一-原文.txt` 和 `南史/-卷一-原文.txt`），只保留一条。

**key 里必须带书名。** 早期版本用的是全局的 `ctx[:45]`，结果《南史》与《宋书》
成段雷同之处只留下路径排序在前的那一本，而被丢掉的往往正是原始史源——
交叉比对少掉一方，还会误报「单方独载」。带上书名后，书内摺叠照旧，
书间并置不受影响。回归测试见 `tests/test_fixes.py`。

**45 这个数仍是启发式的**，没有依据。太短会在同一部书里误合并，太长会漏合并。

### `_mkchunks(hits, n)` 与 `locate(ev, c)`

`_mkchunks()` 把同一卷的命中窗口先并段（`_merge()`，重叠或紧邻的合成最大连续段，
接缝因此减到最少），过长的切小（`_split()`，`chunks()` 只切不改，偏移可以累加），
再装成块。每块记下各段在**原卷正规化全文**中的绝对偏移：

```json
{"ci": 0, "book": "魏书", "juan": "卷六十一",
 "src": "corpus/魏书/卷六十一.txt",
 "segments": [{"start": 12345, "text": "…"}, {"start": 20880, "text": "…"}],
 "chunk": "…\n……【中略】……\n…"}
```

一块可能含数个**不相邻**的段，接缝以 `SEAM` 标出。`locate()` 据此校验：
引文必须完整落在单一段内，返回 `(绝对起点, 绝对终点)`，否则 `None`。

**为什么不能只做子串测试。** 横跨接缝的引文在 `chunk` 里看似连续，
在原书里却隔了几千字——`ev in chunk` 会放它过关。`tests/test_fixes.py`
第 6 项就是构造这种引文，先断言它确实是 `chunk` 的子串（旧闸门会放过），
再断言 `locate()` 拦下它。

`strict_check(r)` 按 `src` + `ev_start`/`ev_end` 回原卷重新读入、切片、
逐字比对，由 `verify --strict` 调用。缺语料或旧数据无偏移时返回 `None`
（无从核对，不算失败）。

### `alias_candidates(rows)` 与 `apply_aliases(rows, amap)`

见 [06-已知局限](06-已知局限.md)「CLI 的人物归一」一节。要点：只提候选，
歧义不给建议值，合并要人确认，原写法留在 `person_raw`。

### `chunks(text, n)`

按 `[。！？；\n]` 的 lookbehind 切分，累加到 n 字为止。保证不切断句子。

n 默认 1400。太大模型会漏抽，太小会切断人物的上下文。

### `call_api(prompt, key)`

用 `urllib` 直接发请求，不依赖 SDK。返回解析后的 JSON 数组。

解析策略：剥掉 markdown 代码块标记，取第一个 `[` 到最后一个 `]`。模型偶尔会加前言，这样能兜住。

**没有重试逻辑。** 失败就跳过这一段并打印错误。这是有意的——静默重试会掩盖系统性问题。

### 逐字校验

```python
if len(ev) >= 4 and ev in ck:
    ...保留
else:
    dropped += 1
```

**这是整个系统防杜撰的唯一硬保证。**

`len(ev) >= 4` 是为了排除模型返回过短片段（「曰」「之」这种在任何文本里都能匹配上）。

`ev in ck` 是朴素子串匹配。更严格的做法是记录字符偏移再重新切片比对——那篇 Beyond Similarity 论文就是这么做的，能防住「模型拼接了原文中不相邻的两段」这种情况。当前实现防不住。

### `analyse(rows, all_stances)`

纯代码推断层。按人名聚合后逐条应用规则：

1. **终局互斥** — `TERMINAL` 集合内任两者并存，权重 5
2. **成对互斥** — `PAIRS` 里的对，权重 4
3. **纪年歧异** — 同一人同一行为绑了不同 time 字符串，权重 4
4. **终局独载** — 多立场都记其人，但某个终局行为只有一方记，权重 5
5. **人物独载** — 此人只见于部分立场，权重 3
6. **多处互见无冲突** — 兜底，权重 1

第 4 条比第 5 条强：两方都记这个人，说明不是材料散佚，那么单方记其死就更可能是选择性沉默。

**这条规则是跑真实数据时才发现该加的**，不是预先设计的。原本张稷只拿到权重 1，因为他在南北两系都有记载（独载不触发），而「除授」和「被杀」不互斥（硬矛盾不触发）。加了终局独载后跳到 5。

## duizhao.py 关键函数

### `COMPILER` 与 `CAMP`：两条立场轴

v0.2.6 之前只有一条 `STANCE`，把两件事混在一起：**谁修的**，和
**替谁说话**。南北朝两者恰好重合（《宋书》南齐修、记刘宋、依南朝实录），
所以看不出问题。元修三史一下就暴露了：

```python
COMPILER["宋史"] == COMPILER["辽史"] == COMPILER["金史"] == "元修"
CAMP["宋史"], CAMP["辽史"], CAMP["金史"]   # 宋系、遼系、金系 —— 三个
```

`align()` 只比对不同立场，旧版于是**从结构上碰不到宋辽金**。
现在管线一路传的 `stance` 指 `CAMP`（`STANCE is CAMP`），
而 `COMPILER` 留着做两件事：源流判断，以及给「同修」的一致打个折扣
（不同阵营却出自同一次修史工程，其一致不如各自独立成书者有力）。

`CAMP` 也接管了《南史》《北史》：它们**替南／北朝说话**（陣營），
而**是唐修**（编纂），其非独立性由 `DERIVED_FROM` 直接表达——
不再像 v0.2.1 那样借立场标签充当独立性的代理。

### `span_overlap(a, b)`

两书的纪事年代是否重叠。《三国志》（184–280）与《明史》（1368–1644）
之间无论怎么凑人名地名都不是同一件事。无断代资料时不排除，
宁可多报不可漏报。

`align()` 的并置条件是两者之一即可：**源流关系**（同阵营也要比，
《梁书》对其派生本《南史》正是最有价值的一组），或**不同阵营且断代重叠**。

### `DYNASTY_SPAN` / `era_usage` / `check_eras`

`ERAS` 第三栏原是「南／北」且程序从未用过，现改作**朝代**，
`DYNASTY_SPAN` 据此核对元年。不拿「提到这个年号的书」作判准：
追述前朝年号是常态，《宋史》提「开元」九次，那不是错，是宋人引唐事——
初版拿它作判准，26 条全是假警报。

`era_usage()` 有两道守卫，都是真语料上吃过教训才加的：

- **子串**：短年号是长年号的后缀时要排除。「大通五年」在本语料里
  三处全是「中大通五年」的一部分。
- **孤例**：只采出现 ≥2 次的最大年次。《宋史》律历志
  「苟以天道时刻预定乾道十二年」，那个「乾道」是易义的天道，
  不是孝宗年号（乾道只有九年）。

### `coverage()` / `cmd_cover`

逐书数门类（檔名形如「列传_卷三十五」）、列传卷数、年号覆盖、阵营、对手。
`bio_juan()` 对整书未分门类者回传 `None`——**不假装数得出来**。

### `DERIVED_FROM` / `derivation(a, b)` / `independent_witnesses(books)`

源流关系表与据此算出的独立史源数，定义在 `huijian.py`，与 `STANCE`
同处；`duizhao.py` **import 而不复制**——UI 层曾因为自己重写一份判断
逻辑而与 Python 层漂移，不再犯第二次。`BOOK_SPAN` 同样已从
`duizhao.py` 移到 `huijian.py`，两处共用一份。

```python
DERIVED_FROM = {
    "南史": {"宋书", "南齐书", "梁书", "陈书"},
    "北史": {"魏书", "北齐书", "周书", "隋书"},
    "新唐书": {"旧唐书"}, "新五代史": {"旧五代史"},
}
```

`derivation(a, b)` 回传 `(派生本, 史源)` 或 `None`，顺序无关。
注意《宋书》与《晋书》虽同为唐修前后，**并无**源流关系——两者题材
相邻而各自成书，是货真价实的独立比对。

`independent_witnesses(books)` 回传 `(独立史源集合, [(派生本, 理由)])`。
**史源缺席时派生本自身仍算一个证人**：《宋书》《南齐书》缺列传，
《南史》往往是唯一所存，此时它所存的可能正是已散佚的史源文字。

每个人物的分析结果带 `witnesses` 与 `derived` 两个字段，报告头行印出
「独立史源 N」。

### `_relevant_stances(books, all_stances)`

只拿纪事年代重叠的书来问「为什么它不记」。《三国志》（184–280）不记
张稷（卒 513）不是讳饰。无 `BOOK_SPAN` 资料的书不参与筛选——宁可多报
不可漏报。

### 「孤证」与「仅见于」的分流

只有一个独立史源时，「仅见于某系」是**同义反覆**：它必然成立，不含
任何立场信息。这类人物改报「孤证：仅一个独立史源」，权重 0。
实测本案例 24 人里 19 人如此（详见 docs/06「四点六」）。

### `to_year(text, book=None)`

从「延昌二年」这样的字符串抽出公元年。

流程：`era_candidates()` 遍历 `ERAS`（已按年号长度倒序），正则匹配
`年号 + 中文数字 + 年`，用 `cn_num()` 转数字，得到 `元年公元 + n - 1`。
取名字最长的那个年号，收集它的全部同名候选：

- 只有一个候选 → 直接返回。
- 多个候选 → 用 `BOOK_SPAN[book]`（各书记事的大致起讫）筛，唯一才返回。
- 其余一律 **None**。

**同名年号必须消歧。** 历代重用的年号字面完全相同：`泰始二年` 在《晋书》
是 266，在《宋书》是 466；`建武二年` 在《后汉书》是 26，在《南齐书》是 495。
早期版本每个名字只收一个元年，于是给出相差一两百年的公元数，
而错误的年份还会在 `pair_score()` 里加 3 分，凭空造出「同年」锚定。

**未收年号、无书名可据、消歧后仍不唯一，都返回 None**，不做任何外推。
`anchors()` 会把该条记载的 `book` 传进来，所以正常流程里书名总是有的；
命令行 `eras` 子命令可以用 `--book` 指定。

已知缺陷：
- 不处理改元当年的月份边界。如果某年五月改元，那年前五个月属于旧年号，这里会算错一年。
- `BOOK_SPAN` 的断限是宽松取的。一部书追述前朝年号时（如《晋书》提曹魏太和），
  候选可能落在本书跨度之外而换算失败——宁可返回 None，不猜。

### `text_ratio(a, b)` 与 `COPY_RATIO`

源流对的锚定一致**一分不计**（雷同是抄录），只算其出入。但「`diverge()`
一条都没归出类」不等于「此处无异」——词表叫不出名字的差异照样是差异。
所以先比两段引文的相似度：

- ≥ `COPY_RATIO`（0.88）→ 纯抄录，不报。
- < 门槛而仍归不出类 → 报「出入未能归类，须人工比读」，权重 1。

这一条是补一个自作的回归：初版「没有已分类的出入就 `continue`」把
《梁书》「斩东昏」对《南史》「杀帝」整组丢掉了。`tests/test_fixes.py`
的 15e 钉死它。

### `pair_score(a, b)`

三重锚定打分。事件层没有姓名这种硬锚点，所以靠人物、地点、纪年、行为四个维度叠加。

权重 3/2/3/1 是拍的。

### `lex_tags(text)` 与 `diverge()`

立场词表匹配加分歧分类。

`diverge()` 输出四类：纪年歧异、立场用语对立、蔑称、行为不重叠。

### `align(rows, threshold, cross_stance_only)`

两两组合（`itertools.combinations`），过阈值的留下。

**复杂度是 O(n²)。** 目前 n 是单次检索命中的抽取条数（几十到几百），没问题。如果要放大到语料级，这里必须先做粗筛。

## 要扩展的话

按价值排序：

1. **span 偏移**而非子串匹配（防拼接式伪引）
2. **CLI 接入人物归一**（目前只有 React 版有，CLI 里「善明」和「刘善明」算两个人）
3. **纪年的月份边界**处理
4. **独载检测的基线分布**——需要知道「同类人物在该类书中的正常著录率」，才能区分讳饰与体例
5. **事件层的实体对齐**——目前靠字符串相等，应该用归一后的 id
